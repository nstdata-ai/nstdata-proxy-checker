# Nstdata Proxy Checker

[中文](README_zh.md)

Check HTTP status, request duration and optional content assertions through HTTP/HTTPS proxies, with optional exit-IP probing. Includes a CLI, Node.js checking library and reusable transport. Use an existing proxy URL or obtain one with your Nstdata API key.

## Install

Supports Node.js 22 (22.18 or later) and 24.

Install the command-line tool; no Node.js project is needed:

```sh
npm install --global @nstdata-ai/proxy-checker
```

## Quick start

Set the proxy connection in the same terminal. Replace the example URL below with the full HTTP/HTTPS URL generated by your proxy provider, including any required username and password. This is not the target website URL.

```sh
export NSTDATA_PROXY_URL='http://user:password@proxy.example:8080'
```

Then check the target:

```sh
nstdata-proxy-checker --target https://example.com/ --timeout 20000
```

Proxy URLs can contain credentials; keep real values out of shared shell history and public logs. The CLI reads the current shell environment and does not load `.env` files automatically. Missing proxy configuration produces setup guidance. Run `nstdata-proxy-checker --help` for options and examples.

Output defaults to JSON. `ok: true` means the target returned 2xx; `statusCode` is its HTTP status and `elapsedMs` measures the request through complete body reading/decoding. Inspect `error.code` on failure; input errors also include `error.message`. See the [result fields](docs/guide.md#content-and-results).

Checks use real proxy traffic. By default, each valid entry makes at most one target GET, including duplicates, without redirects, retries, rotation or direct fallback. A 2xx response does not establish expected content, exit identity or PM routing. Add `--expected-text` to assess content.

`--ip-probe` explicitly adds one IP echo GET. A rotating proxy can use a different exit for the extra probe. Location/ISP/ASN enrichment requires a [separately supplied lookup provider](docs/guide.md#optional-lookup-integration).

## Use an Nstdata API key

Save an authorized Proxy API key in a local `.env` file:

```dotenv
NSTDATA_API_TOKEN=your-api-key
```

Then obtain one HTTP proxy and check the default target:

```sh
nstdata-proxy-checker --nstdata --env .env --yes
```

This requires available balance and a compatible product. It reuses an SDK default channel or creates one, generates one connection, and checks `https://example.com/` once. Proxy traffic is metered; it does not purchase a package. Use `--target` for your own target.

In a terminal, run `nstdata-proxy-checker --nstdata` to enter the key with hidden input and confirm the selected setup. Nothing is written to a credential file. For scripts, `--yes` accepts setup without prompting. [Options and failure recovery](docs/guide.md#nstdata-setup).

## Other installation methods

Run temporarily without a global installation or project dependency:

```sh
npx --yes --package=@nstdata-ai/proxy-checker \
  nstdata-proxy-checker --help
```

For a check, configure `NSTDATA_PROXY_URL` or choose `--nstdata`, then replace `--help` with the check options. The npm package is `@nstdata-ai/proxy-checker`; its executable is `nstdata-proxy-checker`.

To call the library from a Node.js project, use the project's existing package manager:

```sh
npm install @nstdata-ai/proxy-checker
```

Use `pnpm add @nstdata-ai/proxy-checker` in pnpm projects. To run the CLI from a project that already has the package installed, use `npx --no-install nstdata-proxy-checker`.
